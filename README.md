# Idle RPG

A production-ready **2D mobile idle RPG** MVP: a three-hero party auto-battles endless stages while the
player buys stat upgrades, ascends for permanent bonuses and collects offline earnings.

Target: **Unity 6000.6.0f1**, URP 2D, portrait, iOS + Android.

---

## Quick start

1. Clone and open the project in Unity 6000.6.0f1.
2. Open `Assets/IdleRPG/Scenes/Main.unity` (**not** `SampleScene`).
3. Press Play. The scene is fully self-wired: combat, UI, save system and offline progress all run
   from that one scene.
4. First launch pays nothing offline and writes `savegame.json`; later launches restore progress and
   may show a "welcome back" popup.

Everything in the scene is generated by editor tooling, so nothing has to be wired by hand:

| Menu | What it does |
|---|---|
| `Tools > Idle RPG > Build MVP Scene` | Rebuilds `Main.unity` from scratch (Canvas, HUD, pages, popup, EventSystem) |
| `Tools > Idle RPG > Generate Data Assets` | Regenerates heroes, enemies, upgrades and config ScriptableObjects |
| `Tools > Idle RPG > Generate Placeholder Sprites` | Regenerates the procedural art set |
| `Tools > Idle RPG > Debug > Log Balance Summary` | Balance table: pacing, TTK, gold/sec, token yield, **offline payouts** |
| `Tools > Idle RPG > Save > ...` | Open save folder, dump the save, delete it, fake a 3h absence |
| `Tools > Idle RPG > Content > Export / Generate / Validate` | Recipe-card (JSON) content pipeline: export current values, apply cards, or validate the catalog |
| `Tools > Idle RPG > Mobile > Verify Settings` | Audits portrait lock, IL2CPP/ARM64, min OS versions, bundle ids, build scenes |
| `Tools > Idle RPG > Mobile > Apply Recommended Settings` | Applies those mobile settings (leaves bundle ids alone) |

## Architecture

```
Assets/IdleRPG/
  Scripts/
    Core/        GameManager (composition root + FSM), GameState, GameEvents, GameClock,
                 MobileRuntimeBootstrap
    Data/        ScriptableObjects: HeroData, EnemyData, WaveConfig, BalanceConfig, PartyConfig,
                 StatUpgradeData, PrestigeUpgradeData
    Combat/      CombatSimulator (pure C#), CombatManager, combatants, CombatScaling/rewards
    Economy/     EconomyManager (gold/gems/tokens), BoostManager, EconomyRateTracker
    Progression/ FormulaUtility (all maths), StatResolver, UpgradeManager, AscensionManager
    Save/        SaveData, SaveSystem, SaveManager, SaveMigrations, IdleTimeService
    Services/    IAdService, MockAdService (SDK-ready)
    UI/          ScreenController, HudController, panels, views, log, popup, SafeAreaFitter
    Utils/       NumberFormatter (K/M/B/T/aa...)
  Editor/        MvpSceneBuilder, DataAssetGenerator, PlaceholderSpriteGenerator, UiFactory,
                 debug menus, MobileBuildSettingsUtility
  Data/          generated .asset files     Scenes/  Main.unity (+ CombatDebug.unity)
  Art/Placeholder/ generated PNG sprites    Settings/ persisted UI input actions
```

Design rules that keep the project testable:

- **`CombatSimulator` is pure C#** with a seeded RNG, so live combat, offline estimates and headless
  balance runs share exactly one code path.
- **`GameEvents`** is a static `Action` bus (reset on load); UI binds to events, never polls in `Update`.
- **All tunables live in ScriptableObjects.** New hero, enemy or upgrade = new asset, no code change.
- **`BalanceConfig.combatPaceMultiplier` is the single game-pace knob**: it stretches every attack
  interval (heroes and enemies) so difficulty tuning never needs a rebalance.
- Anything on a page that starts inactive binds lazily (`EnsureBound()` from `Start` **and** `OnEnable`)
  and never disables itself; `FindAnyObjectByType` skips inactive objects, so probes use
  `FindObjectsByType(..., FindObjectsInactive.Include, ...)`.

## Gameplay systems

| System | Summary |
|---|---|
| **Combat** | 3 heroes (Knight/Archer/Mage) vs a rotating enemy pool; 10 normal waves + 1 boss per stage. Damage = `max(ATK − DEF, ATK × 0.15)`, 5% crits at ×2, and every attack interval is stretched by `combatPaceMultiplier`. Bosses pay +1 gem and ~half a stage of gold. |
| **Defeat** | Party wipe only (no boss timer). Rollback 1 stage, auto-retry switches off; manual retry resumes at `stage − 1`. |
| **Progression** | Per-hero stat upgrades (ATK/HP/DEF) on a 1.07 cost curve with closed-form bulk buys (+1 / +10). Ascension trades the run for prestige tokens (`floor((bestStage / 10)^1.5)`), resetting gold, stage and hero levels while keeping gems, tokens and permanent upgrades. |
| **Economy** | Gold (combat), gems (bosses), prestige tokens (ascension). A single funnel, `ResolveGoldReward`, applies prestige multipliers and the ad boost to every gold source. |
| **Monetisation** | `MockAdService` (3s simulated rewarded ad) behind `IAdService`; a ×2 gold 1h boost, extendable by watching an ad. |
| **Offline** | Dual capped: 8h wall-clock (spec) **and** 2h of equivalent battle income. `gold = paidSeconds × goldPerSecond × 0.7`, where the rate is the measured 60s rolling income, the save's stored rate, or a formula estimate, in that order. A rewound clock pays 0, a claim can only be taken once, and offline gold never feeds the live rate measurement. |

Balance numbers print from `Tools > Idle RPG > Debug > Log Balance Summary`, including a
1h/2h/8h/9h × stage 1/10/30 offline payout table.

## Save data

| Item | Value |
|---|---|
| Files | `savegame.json` + `savegame.json.bak` in `Application.persistentDataPath` |
| Writes | atomic (`.tmp` → replace), previous file kept as `.bak`, unreadable file quarantined as `savegame.corrupt-<timestamp>.json` |
| Cadence | every 15s, plus debounced saves (≥5s apart) after kills, stage clears, upgrades and ascensions, plus pause, focus loss and quit |
| Schema | v2 (`schemaVersion` header + `SaveMigrations`; v1 files upgrade additively) |
| Lifetime stats | `totalKills`, `totalGoldEarned`, `playTimeSeconds`, `ascensionCount`, `saveCount`, `lastPageIndex` |
| Timestamps | `lastSaveTimestampBinary`, `lastLogoutTimestampBinary`, mirrored to PlayerPrefs `IdleRPG.lastLogout` |

On the desktop Editor the folder is `~/Library/Application Support/DefaultCompany/Idle RPG/`
(macOS) or `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Idle RPG\` (Windows); on device it is the
app sandbox. Set a real `companyName` before store submission (it moves that path).

## Debug tooling

**Hotkeys in Play mode**

| Key | Action |
|---|---|
| `Tab` | Cycle pages (Battle / Upgrades / Ascend / Shop) |
| `1` / `2` / `3` / `4` | Buy +1 ATK / +10 ATK / +10 HP / +10 DEF for every hero |
| `F3` | Dev overlay: party DPS/eHP, gold per minute, wave ETA, rng state, save info **+ the full hotkey list** |
| `F5` / `F9` | Save now / delete the save file |
| `F10` | Rewind the logout clock by 3h **and** re-run the offline calculation (payout + popup) |
| `G` / `T` / `C` | Grant test gold / prestige tokens / gems |
| `B` / `A` / `R` / `S` | Watch ad for the gold boost, request ascension, retry after defeat, skip to the next stage |
| `F` | Buy instant income (gem sink #2) through the real shop path |
| `M` | Mute / unmute the placeholder SFX |
| `L` | Log live state (stage, economy, rates, save info) |
| `F8` / `F9` | **Full reset** (save + backups + PlayerPrefs + scene reload) / delete the save file only |

The list above is generated from `DebugHotkeyCatalog`; the same legend is printed by the `F3` overlay and by
`Tools/Idle RPG/Debug/Log Hotkeys`, so the three can never drift apart.

**Editor menus** — see the Quick start table; `Save > Fake 3h Offline` offers the popup on the next
launch, and `Debug > Log Live State` dumps the running game without touching the UI.
`Save > Reset Game Completely` is the same fresh-install wipe as `F8`, and `Debug > Log Hotkeys` prints the list
above.

**Placeholder presentation (Step 9b-3)** — SFX are procedural tones (`PlaceholderAudioService`, no audio files);
volume and mute persist in PlayerPrefs and are wiped by a full reset. Currency icons are generated PNGs wired
onto each `CurrencyDef.icon`; Step 19/20 replace art and sound without code changes.

## Testing

The project deliberately has no automated test suite (`.clinerules`); verification runs through the
debug menus, the console log and the Unity MCP bridge. A manual pass takes ~5 minutes:

1. **Combat / pacing** — Play, watch the log feed, confirm stage 1 clears in ~2 minutes and the boss
   wave pays gems.
2. **Progression** — buy upgrades on UPGRADES, ascend on ASCEND, buy a prestige upgrade, then check the
   header values moved.
3. **Persistence** — buy things, stop, Play again: gold/stage/hero levels restore (`Save load: file`).
   `F5` saves, `F9` wipes, and corrupting `savegame.json` recovers from `.bak`.
4. **Offline** — press `F10`: the popup shows `3h 00m away`, the capped payout and the cap note;
   claiming pays exactly the shown amount and a second click pays nothing.
5. **Mobile settings** — `Tools > Idle RPG > Mobile > Verify Settings`; every line should read `OK`.

## Building

1. `Tools > Idle RPG > Mobile > Verify Settings` → expect `RESULT: all good.`
2. `File > Build Settings`: only `Assets/IdleRPG/Scenes/Main.unity` is enabled.
3. Android: IL2CPP + ARM64, min API 26. iOS: IL2CPP, iPhone + iPad, min iOS 15.
4. Bundle identifiers are `com.siddharth.idlerpg` on both platforms — change them if you fork.
5. `MobileRuntimeBootstrap` applies the device policy on launch (60 fps target, vSync off, screen kept
   awake, run-in-background off) and logs a one-line device summary. It is skipped inside the Editor.
6. A macOS player build was verified: it logs the device summary, loads the save file, pays capped
   offline earnings and runs combat with no exceptions. Local builds land in `Builds/` (gitignored).
